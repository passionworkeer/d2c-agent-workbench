# 三个真实活动页的本地实跑记录

在「活动页生产」选择商城、游戏节或养萌宠，再点顶栏「运行 Mock 演示」。现有图片对照、执行轨迹、评测及下载区域直接恢复该页的实际运行；不新建演示面板，也不调用生产接口。

左侧为原图，右侧默认运行真正的 React 页面，两栏顶部和高度齐平。点击「页面交互」可操作原组件；「组件检查」通过 iframe 内真实 DOM 框选节点，显示实际尺寸与源码位置，检查点击不触发业务操作，Esc 取消。可「新窗口打开真实页面」，或切到「运行截图」查看当时的浏览器实拍。Figma 区域移到两栏下方，默认收起。

交互预览由已保存的运行结束 TSX/CSS 快照与目标仓库共享组件重新打包，不是图片热区。`production-previews/build-manifest.json` 记录参与构建的源码 SHA-256；预览构建时间与历史 Run 时间分别保存。运行日志/评测仍是原始实跑记录，不随演示中的点击更改。

每包包含 14 个真实事件、每步输入和输出、命令 stdout/stderr/退出码、运行结束源码快照、两视口 PNG 及完整评测。三个 Run 均为 COMPLETED，无 P0/P1；P2 差异仍如实保留。语义评审未配置在线模型，记录明确标注 registered-fallback，不能称为现场模型评审。

这些静态 JSON 随前端构建发布，不受后端历史清理和工作区删除影响。代码下载包含本次生成文件，需要现有 examples/activity-target 的组件与依赖，并非独立项目。Figma 渲染仍需导入真正的 Figma 导出图；演示包不伪造 Figma 截图。

重新执行三页的「运行生产闭环」后，可运行 `pnpm demo:record` 保存各页最新成功记录并构建交互预览。需指定 Run 时，先按表格顺序传三个 ID 给 `node scripts/record-production-demos.mjs`，再运行 `pnpm demo:build-previews`。脚本仅接受证据完整、构建成功、有源码快照及 PNG 的记录；用 `pnpm demo:check` 验证。仅演示时无需重新运行脚本、启动目标项目服务或启动后端。
