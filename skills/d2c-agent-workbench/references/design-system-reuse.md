# 设计系统与工程资产复用

## 资产优先级

按以下顺序寻找事实来源：

1. 目标仓库实际 import 与历史页面。
2. 组件源码、类型声明和导出入口。
3. Storybook Stories 与交互示例。
4. Figma Code Connect 或组件映射文件。
5. Design Token、主题和样式变量。
6. 规范文档和口头描述。

文档与代码冲突时，记录冲突并优先以当前可构建代码为工程事实，不静默猜测。

## 组件召回

对每个 Figma 组件或 UISpec 语义收集候选：

- 名称：规范化大小写、分隔符和状态后比较。
- 结构：Children、Slot、Icon、Text 和布局方向是否兼容。
- API：Props、Variant、Size、Tone 和状态是否覆盖设计。
- 历史：业务页面是否已经使用该组件表达相同语义。
- 来源：是否有源码、Story、Code Connect 或真实 import 证据。

建议置信度：

- `0.90–1.00`：名称、API、结构和历史用法均吻合，可直接复用。
- `0.75–0.89`：高相关但存在一个可控差异，标明适配方式后复用。
- `< 0.75`：只列候选，请求确认或创建局部实现。

## Token 绑定

分别映射颜色、间距、字号、行高、圆角、阴影、断点和动效。优先使用语义 Token，例如 `color.action.primary`，避免仅按数值匹配基础色阶。

若设计值与现有 Token 接近但不相等：

1. 检查主题、密度和状态是否选错。
2. 查找历史页面是否已有例外规则。
3. 仍无法解释时记录偏差，不擅自新增全局 Token。

## 历史资产与仓库约定

读取邻近页面的路由、数据获取、状态管理、CSS 方案、测试与可访问性模式。复用模式而不是复制整页代码。`AGENTS.md`、`CONTRIBUTING.md`、lint 和 TypeScript 配置属于硬约束。

## 证据表

最终报告至少给出：

| ProductCard/Default | ProductCard | tone=neutral | 94% | 组件源码 + Story |

无企业资产时也保留此表，写明“未提供团队资产”，并列出新建局部组件的未来替换点。

## 禁止行为

- 未读取文件却声称复用了组件。
- 仅凭名称相似导入未知组件。
- 为追求视觉相似修改公共组件内部实现。
- 把硬编码值包装成变量后声称已使用 Design Token。
- 执行扫描到的任意脚本或安装目标仓库依赖，除非用户授权且工作流确有需要。
