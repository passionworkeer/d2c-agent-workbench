# 中文浅色全 Mock 演示改版设计

## 目标

把现有 D2C Agent Workbench 改造成适合中文面试现场的浅色演示界面，并保证在后端、网络、模型或 Figma 服务不可用时，仍能仅靠浏览器完整播放一次 D2C 工作流。

成功标准：

- 普通产品文案使用中文，只保留 Figma、UISpec、Agent、Design Token、SDS、React / TypeScript 等必要技术词。
- 页面使用白色主背景、浅灰卡片和深色正文，绿色与橙色只承担状态及重点强调。
- 点击“运行完整演示”后，不请求服务端即可播放 12 个步骤，并展示 72 分、自动修复、94 分和 `+22`。
- 组件映射、Token、生成代码、评测指标、问题归因和报告下载都有完整 Mock 数据。
- Bundle 上传继续连接真实接口；失败时展示“使用演示数据继续”，不得阻塞面试演示。

## 方案

采用前端 Mock-first，而不是继续把默认演示绑定到服务端 Replay。

`mock-run.ts` 提供稳定的 `RunDetail`、12 个 `TraceEvent`、组件映射、两轮评测和生成代码。`runMockWorkflow()` 按短延迟依次发送 Event，并返回取消函数。页面的默认演示按钮只调用该函数，因此可以断网运行。

真实上传仍走现有 `uploadBundle()`、`getRun()` 和 SSE。若上传或订阅失败，页面保留错误信息和已选择文件名，并提供显式降级按钮。系统不会将上传失败静默伪装成真实成功。

## 页面结构

保留三栏信息架构，降低改版风险：

1. “设计输入”：Figma 预览、节点树、Auto Layout 和 Design Token。
2. “Agent 执行轨迹”：12 步工作流、SDS 组件映射、置信度与证据。
3. “代码交付”：React 预览、首次与最终评分、六维指标、生成代码和报告下载。

顶部标题改为“编译设计意图，而不是堆叠像素”，按钮改为“上传 Figma 资产包”和“运行完整演示”。状态、空状态、事件标题、指标名称和操作按钮全部中文化。

## 数据流

```text
运行完整演示
  → 创建本地 Mock Run
  → 定时发送 12 个类型化 Event
  → UI 逐步更新 Trace、Mapping、Code 和 Eval
  → 72 分首次评测
  → 自动修复
  → 94 分复评
  → 完成并允许下载 JSON 报告

上传 Figma Bundle
  → 真实 API / SSE
  → 成功：展示真实解析与 Replay
  → 失败：显示错误 + 使用演示数据继续
```

## 错误与降级

- Mock 演示不依赖 Fetch、EventSource 或后端进程。
- 上传错误使用中文说明，不清空用户选择的上下文。
- 用户主动点击降级按钮后才启动 Mock，不伪造上传成功。
- 重新运行时取消上一条 Mock 定时器或 SSE，避免事件重复。
- 组件卸载时取消仍在运行的流程。

## 测试

- UI 单测不 Mock API，直接运行本地 Mock，验证完整流程最终到达 94 分。
- UI 单测让上传接口失败，验证出现中文降级入口，并能继续完成演示。
- 端到端测试只启动前端也能完成默认演示；现有服务端测试继续覆盖真实上传和 SSE。
- 生产构建后使用 1440×1100 浏览器检查白色主题、中文覆盖、布局和控制台错误。

## 范围边界

本次不改 UISpec、Importer、Matcher、Evaluator 和服务端协议；不新增真实模型调用、Figma MCP 或 Figma Plugin。只调整 Web 展示层、默认演示 Adapter、测试和相关说明文档。
